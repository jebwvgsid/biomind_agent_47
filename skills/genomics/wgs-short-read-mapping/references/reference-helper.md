# Stable reference preparation

Call the registered `scripts/prepare_reference.py` directly using its published argv contract. Pass `--source` and `--output` from the current formal reference input and bundle output, `--reference-ref` and `--artifact-ref` from those same current resource identities, and `--bwa`, `--samtools`, `--picard`, `--java` from the exact approved runtime bindings. Do not substitute PATH discoveries. The helper consumes controller `BIOMIND_TASK_ID`, `BIOMIND_STEP_ID`, `BIOMIND_ACTION_ID`, `BIOMIND_ATTEMPT_ID`; never assign or invent those values in generated code.

Declare `--work-dir` as the formal auxiliary output with role `reference_preparation_evidence` and pass its exact resource identity as `--evidence-artifact-ref`. Include this output in the approved Plan and complete code approval; its role lets the frozen v2 parser distinguish it from the one scientific bundle. It contains local ownership/publication receipts, per-command stdout/stderr and uniquely named staging directories. It must be on the output filesystem, outside the immutable bundle and source. It is not a second scientific result or a global database. Do not point it at shared environments, another task or legacy benchmark results. Retain this same owned control directory for an approved retry/revalidation; each actual execution attempt receives its own build directory and receipt.

The source is read-only. The helper copies and hashes it, runs BWA index, samtools faidx and Picard CreateSequenceDictionary with `R=`, `O=`, and standard `URI=` encoding for the **final** reference.fa location. Java/PATH select the bound Java explicitly. Required command errors stop construction, retain native returncode and logs, and make the wrapper fail. A killed command remains killed with unknown resource cause unless independent evidence establishes one. No installation, fallback implementation or OOM guess occurs.

The same production parser validates each reusable component and the complete bundle before publication. Staging validation opens staging FASTA explicitly; it compares dictionary UR to the final URI without following it. Publication uses same-filesystem no-replace rename, fsync, a scoped OS lock and a durable prepared inode/content receipt. Unsupported no-replace publication fails without a weaker overwrite fallback. After publication, the parser validates final files again. An external publisher occupying the target is protected, even if it did not take the helper's lock.

A known failed owned build may donate only components with recorded successful validation whose current source, file hashes and content validate again; other files stay in that old build and are rebuilt in a fresh attempt. The helper never treats an arbitrary existing directory as its own. An already-published same-task candidate is accepted for **revalidation only** when its inode agrees with the prepared journal and every content hash/scientific check still agrees. It does not repeat tools after a crash between publication and the published receipt, and does not modify existing candidates. Unknown targets, changed published files and owner/scope mismatches fail closed.

The emitted reference_bundle_valid observation and create_reference_indexes fact are actual helper results, not Commit authority. The existing runner/provenance, frozen Skill, independent v2 reference parser, CompletionGate, Supervisor and Commit path must still accept them. Published status is `published_uncommitted`; neither directory visibility nor the local journal changes Plan state. Frozen Plans with a required nonexistent observation directory still require formal Plan revision; do not manufacture directories to satisfy them. Unknown Q mapping is unaffected.

## 复用能力与必要适配

直接复用上游的设置解析、优先级、正整数校验、默认值、tailTools、原生阈值警告、tool_result 扩展机制，以及 Pi 公共 truncateHead/truncateTail。没有另建输出服务、作业框架、全局扫描、摘要模型或自动清理器。

BioMind 补丁集中于以下边界：

- 一个工具的所有文本块共用正文预算，附件保持原位置。状态、来源、遗漏说明单独保留，所以最终文本字节数可以超过 8192；不设 10000 字符总上限。
- 识别当前 Pi/BioMind 的原生脚注和真实执行状态。原生错误返回只有文本中含完整日志路径时也恢复来源；不更改 isError、退出码、取消/超时语义，不重试计算。
- read 复用成功读取时的原始路径参数和 cwd；按实际显示完整行数续读。超过预算的单行返回计算端按字段/字符段读取方法，不错误递增行号或原地循环。
- BioMind 在现有公开回执投影之后、JSON.stringify 之前裁正文/候选数组；保留 JSON 结构、状态、run_ref、binding_ref、错误和来源。已有分页内容不再次裁切。已有可读 receipt_ref/log_refs 优先复用，否则仅保存已经公开的工具返回，绝不绕过权限读取底层私有记录。
- 通过宿主内部 output.configure 将生效预算传给原有 Python 读取器；这不是模型工具，不增加工具参数。read_run_log 使用同一共享预算生成正文，再按真实消耗源字节签发原有不透明游标；不拿 UTF-8 重新编码长度冒充原始日志字节偏移。脚本、命令、记忆沿用原有 Unicode 码点偏移并以真实返回长度更新 next_offset。
- inspect_run 的脚本/命令页保留 log_refs，不同时返回会误导继续位置的未展示日志页。日志缺失/轮换仍与作业状态分开报告；查询异常不能把科学失败改成成功。
- 每个会话在 Pi 的 systemPromptOptions.sections 中设置一份插件说明，保留 Pi/BioMind 提示词组合。主提示词仅逐字新增附件第七节规则一次，其他 COMMON/PROTECTED/MAINTENANCE_RULES 与基线逐字一致；实际模型请求工具定义与基线相同。

## 来源与存储

优先级：原生全文文件/既有执行记录与日志 → 原文件 → 私有临时文件保存“本次已公开返回”。私有保存使用项目内随机 `.pi-output-limits-*` 目录（0700）和排他创建的 output.log（0600），并发不覆盖。只写已经返回给工具层的内容，不另读受保护文件；写入拒绝时保留真实状态并明确无法恢复，绝不伪造路径。

原生 `/tmp/pi-bash-*.log` 与插件临时预览均可能被系统/人工清理，不能当永久科学证据；跨会话科学日志仍由现有持久作业目录管理。测试隔离目录中的科学文件只是固定夹具。本轮无自动清理，回退不删除会话引用的日志。失效原生路径测试只保证可恢复已收到片段，完整原文不可恢复明确标记，不将故障注入场景列为全文恢复 PASS。

BioMind 智能体如何处理一个 scRNA 标准分析任务

这份 HTML 按当前代码梳理，不是理想化流程图。它展示每个阶段搜索了哪些知识、收集了什么上下文、写入哪些状态字段，以及传给下一个阶段的内容。

入口：BioAnalystAgent.go() 图引擎：LangGraph StateGraph 案例：scrna_standard_analysis

案例输入

选择单细胞标准分析作为示例，因为仓库里已经有完整 workflow 模板和多阶段 skill。

用户请求示例：
“请对 manifests/gse96583_ingest_qc.yaml 对应的单细胞数据做标准分析。
先完成 ingest 和 QC，再继续预处理、聚类、marker 查找和细胞类型注释。
如果环境缺失，请先安装或复用合适环境。”
Workflow 模板 workflows/scrna_standard_analysis.yaml 定义 7 个阶段，batch 1 只激活 ingest + QC。
Skill 来源 skills/scrna/*/SKILL.md 提供执行脚本、输入输出、runtime 和 healthcheck。
执行产物 计划、脚本、stdout/stderr、验证结果写入 task_outputs/<task_id>/ 和 SessionArchive。
人工节点 计划审批、代码执行确认、环境选择和缺失参数都会中断等待用户。

主链路图

Managed 任务的核心循环是 Generate -> Execute -> Supervisor -> Generate；轻量任务会绕过 Consultant/Planner/Supervisor。

0. go()

初始化任务状态
  • 创建 task_id
  • 加载 CoreMemory
  • 写入 stable prompt

1. Triage

快速四分类
  • chat
  • readonly
  • simple_execute
  • managed

2. Consultant

知识经纪人
  • 搜 workflow/skill
  • 搜 Wiki/Archive/RAG
  • 验证输入路径

3. Planner

详细计划
  • 加载 active skill docs
  • 生成 checklist
  • 保存 plan.md

4. Plan Review

人工审批
  • 批准进入执行
  • 反馈返回 Planner
  • 取消则结束

5. Generate

单步动作生成
  • <execute>
  • <search>
  • <install_tool>
  • <solution>

6. Execute

代码审查与运行
  • runtime guard
  • 保存脚本
  • 收集 stdout/stderr

7. Supervisor

科学性审查
  • 规则检查
  • 必要时 LLM review
  • PASS/WARN/RETRY

8. Finalize

记忆归档
  • TaskSummary
  • SessionArchive
  • Wiki ingest

安装分支

Generate 或 Execute 发现 runtime/包缺失时进入 install_subagent，确认环境后运行 InstallerAgent，完成后回到 Generate。

问用户分支

Consultant 或 Generate 输出 ASK/<ask_user> 时进入 ask_user，用户答案作为 <human_answer> 回到原阶段。

批次切换分支

工作流后续批次通过 <activate_batch batch_id="N" /> 激活，未来技能才会进入 active skills。

阶段明细：搜寻、收集、传递

默认展开的是 managed scRNA 案例路径。按钮可快速展开或折叠全部阶段。

Triage
判断任务是否进入完整智能体流程
route
搜寻/读取
  • 读取用户最新请求文本。
  • 调用 classify_task_mode()，让 LLM 返回 JSON 路由。
  • 不查本地文件，不查 RAG，不查技能正文。
收集
  • task_mode=managed
  • retrieval_mode=kb
  • validation_level=scientific
  • use_scientific_review=true
传递给
  • managed -> Consultant
  • readonly/simple_execute -> Generate
  • chat -> Direct Chat
Consultant
广域检索、需求审计、workflow/skill 选择
memory broker
搜寻/读取
  • WorkflowManager 读取 workflows/*.yaml。
  • SkillManager 读取技能树、浅层 catalog、必要时 SKILL.md/reference/script。
  • WikiMemoryManager 读取 wiki digest 与相关页面。
  • SessionArchive 检索同项目历史事件和未入 Wiki 的近期事件。
  • TaskSummaryRenderer 查询当前任务/相关任务摘要。
  • 需要外部知识时通过 SEARCH KB_NAME query 调 RAGFlow。
  • 用户给路径时用安全只读 EXECUTE 验证存在性和格式。
收集
  • 已验证输入路径、目标环境、缺失输入。
  • Workflow handoff：WORKFLOW_DECISION、WORKFLOW_STAGES。
  • 当前批次 ACTIVE_SKILLS，后续批次 FUTURE_SKILLS。
  • 把广域记忆压缩成 consultant_memory_packet。
传递给
  • requirements_summary -> Planner/Installer。
  • workflow_handoff、active_batch_id -> Planner/Generate。
  • active_skills、future_skills -> Planner/Generate/Execute。
  • memory_packet_context -> Planner/Generate。
  • rag_history -> Planner/Generate。
Planner
把咨询结果转成可执行 checklist
plan
搜寻/读取
  • 读取 Consultant 的 requirements_summary 和记忆包。
  • 读取已选择技能完整文档、reference index、runtime execution cards。
  • 读取 installed tools 和 workflow handoff。
  • 如果没有 Consultant 记忆包，再补查 Wiki 和 pending archive buffer。
收集
  • 详细计划四段：需求分析、执行步骤、执行 checklist、验证 checklist。
  • plan.md 和 plan_state.json。
  • 计划中的 active/future skill block，并再次验证 workflow handoff。
传递给
  • current_plan -> Plan Review/Generate/Supervisor。
  • plan_progress -> Generate/Execute/Supervisor。
  • 经验证的 selected_skills/active_skills -> Generate。
Plan Review
人工批准或退回计划
HITL
搜寻/读取
  • 读取 current_plan 和当前消息的 memory status。
  • 不做外部检索。
收集
  • 用户批准、取消或反馈。
  • 批准时初始化/持久化 checklist 当前步骤。
传递给
  • 批准 -> Generate。
  • 反馈 -> Planner，并清空当前技能/workflow 状态。
  • 取消 -> Finalize。
Generate
只生成一个当前步骤动作
step-local
搜寻/读取
  • 加载 stable system prompt：CoreMemory、AGENTS.md、工具上下文。
  • 加载当前 active skills 的完整文档和 reference index。
  • 消费 Consultant 的 memory_packet_context。
  • 错误/WARN/RETRY 时按需查 SessionArchive 作为 recovery memory。
  • 缺输入路径时按需查 ArtifactIndex 和 pending archive buffer。
  • 用户追问证据时按需查 Wiki digest/context。
  • 主动输出 <search> 时查 RAGFlow SOP/ERRORS。
收集
  • 下一步动作：<execute>、<install_tool>、<ask_user>、<activate_batch> 或 <solution>。
  • 当前 plan_progress 证据。
  • 生成内容写入 SessionArchive。
传递给
  • <execute> -> Execute。
  • <install_tool> -> Install Sub-Agent。
  • <search> 的结果回到 Generate。
  • <solution> -> Finalize。
Execute
运行脚本并生成 observation
runtime
搜寻/读取
  • 读取 Generate 的 <execute> 代码。
  • 检查 future skill guard，阻止提前使用未来批次技能。
  • 检查 selected skill 的 env_runner 使用是否正确。
  • 检查 runtime 是否 ready；不 ready 则改走安装分支。
  • 执行前通过 HITL middleware 做代码审查。
收集
  • 保存 step_N.sh 或 step_N.py。
  • 收集 stdout、stderr、returncode、duration。
  • 调用 ResultValidator 得到 validation block。
  • 记录成功技能执行和自动发现的 artifact。
传递给
  • <observation> -> Supervisor。
  • 失败 observation -> Generate 重新生成。
  • readonly/simple_execute 任务直接 Finalize，不进 Supervisor。
Supervisor
执行后科学审查与纠错
QA
搜寻/读取
  • 读取最近的 <execute> 和 <observation>。
  • RuleEngine 检查退出码、空输出、静默失败、非进展命令、OOM、生信工具正向信号。
  • 有错误/警告或 scientific validation 时调用 LLMReviewer。
收集
  • supervisor_verdict=PASS/WARN/RETRY/ESCALATE。
  • <supervisor_feedback>。
  • CoT/执行审查日志。
传递给
  • PASS/WARN -> Generate 执行下一 checklist 步。
  • RETRY -> Generate，要求不要重复失败命令。
  • ESCALATE -> Finalize failed。
Install Sub-Agent
环境复用、安装与注册
runtime setup
搜寻/读取
  • 读取 <install_tool>、requirements summary、当前计划。
  • 读取 selected skill runtime metadata、healthcheck、install_tool。
  • 查 runtime registry 和 PackageManager，优先复用已验证环境。
  • 必要时启动 InstallerAgent 子图。
收集
  • 目标 conda/env 名称。
  • 安装结果和 runtime_status。
  • 成功环境写回 skill runtime registry。
传递给
  • 安装 observation -> Generate。
  • 更新后的 runtime_status -> Execute guard。
  • 失败原因 -> Generate 重新决策。

本案例中的跨阶段状态

这些字段是你检查流程优化时最值得追踪的“交接单”。

[WORKFLOW_DECISION]
workflow_id: scrna_standard_analysis
workflow_source: workflow_registry
active_batch_id: "1"

[WORKFLOW_STAGES]
- data_ingest -> selected_skill -> scrna/ingest/data-download -> active
- qc_filter   -> selected_skill -> scrna/qc/filter           -> active
- preprocess  -> selected_skill -> scrna/preprocess/basic    -> future
- cluster     -> selected_skill -> scrna/cluster/basic       -> future
- marker_find -> selected_skill -> scrna/markers/find        -> future
- annotation  -> selected_skill -> scrna/annotate/basic      -> future/block if ref missing
- de_analysis -> optional      -> scrna/de/contrast          -> future
状态字段 来源阶段 用途
requirements_summary Consultant 给 Planner/Installer 使用的确认输入、参数、环境、缺口摘要。
memory_packet_context Consultant 广域记忆检索后的压缩交接包，Planner/Generate 默认只消费它。
active_skills Consultant/Planner 当前批次加载到 Generate 的技能，最多 3 个。
future_skills Consultant/Planner 后续批次技能；Execute 会阻止提前调用。
current_plan Planner Generate 单步执行、Supervisor 判断上下文、Plan Review 展示。
plan_progress PlanTracker 标记当前 checklist 步骤 running/done/blocked，并记录证据。
supervisor_verdict Supervisor PASS/WARN 进入下一步，RETRY 触发 Generate 修复，ESCALATE 结束。
runtime_status Install/Execute 记录环境是否可用，供后续 runtime guard 和提示词使用。

记忆闭环

当前设计把“长期稳定事实、任务过程日志、可复用 Wiki 知识”分开，避免 Generate 每轮都吞大量历史。

启动时加载 CoreMemory CoreMemoryStore.load_snapshot() 生成 stable system prompt。它适合放用户偏好、项目稳定规则、Wiki 索引引用，不适合放具体过程日志。
每个阶段写 SessionArchive _observe_session_memory() 在 consultant、planner、generate、execute、supervisor、install_subagent、finalize 等阶段记录事件、摘要、路径、returncode、task_semantics。
Consultant 做广域自动检索 _consultant_memory_retrieval_context() 汇总 Wiki、TaskSummary、相关 Archive、项目 Archive，然后要求 Consultant 只把相关内容放进 handoff。
Generate 只做触发式按需检索 正常 PASS 流程不重新广域召回；只有错误恢复、缺路径、用户追问证据、显式 <search> 时才查 Archive/Artifact/Wiki/RAG。
结束后生成 TaskSummary，可进入 Wiki _finalize_task_memory() 写任务摘要；根据 BIOMIND_WIKI_INGEST_MODE 自动、询问或手动把 pending events 汇编成 Wiki 页面。

下面是本说明页直接依据的主要模块，方便你回到源码检查。

bio_agents.py

主智能体、LangGraph 节点、状态流、计划审批、Generate/Execute/Install/Supervisor 分支。

execution/*

脚本执行、安全确认、结果验证、错误恢复 middleware、运行监控。

supervisor.py

规则引擎、LLM 科学审查、PASS/WARN/RETRY/ESCALATE 判决和 CoT 日志。

优化检查点

这些不是必须修改的 bug，而是你检查智能体是否还能优化时可以优先看的地方。

中Plan Review 反馈会清空技能/workflow

当前用户拒绝计划后会把 selected_skills、active_skills、workflow_handoff 清空再回 Planner。若反馈只是“小改参数”，可能导致重复选择技能。

低Generate 的任务摘要默认不重查

_generate_on_demand_memory_contexts() 返回空 task summary context，主要依赖 Consultant 记忆包和触发式 Archive/Wiki 检索。这个设计省 token，但要确认不会漏掉长任务中途的关键摘要。

中Consultant 是唯一广域自动检索点

这是清晰的架构边界。优化时建议检查 Consultant 的 FINISH 是否真的把关键记忆转成了 plan constraints，而不是只把原文塞进 summary。

低Active skills 上限保护批次执行

当前最多 3 个 active skills，适合 scRNA batch 1 的 ingest+QC。完整分析靠 activate_batch 推进，避免一次加载全部 skill 文档。

中Execute 的脚本编号取消息长度

step_N.sh 的 N 来自消息数量，重试/搜索/问答多时编号可能不连续。对审计不致命，但可读性一般。

高Supervisor 依赖 observation 文本判断失败

当前会从 observation 的符号和文本提取 returncode/流信息。若未来 observation 格式变化，建议改成结构化 runtime_status 或 metadata 传递。

中RAGFlow dataset 选择较粗

Generate 主动 search 目前按 query 是否含 error 在 SOP/ERRORS 间切换；Consultant SEARCH 由模型指定 KB_NAME。后续可以加入更明确的数据集路由。

低Wiki ingest 模式影响后续检索质量

如果 BIOMIND_WIKI_INGEST_MODE 不是 auto，任务结束后的知识不会自动进入 Wiki，后续任务只能查 pending Archive 或手动 /wiki ingest。

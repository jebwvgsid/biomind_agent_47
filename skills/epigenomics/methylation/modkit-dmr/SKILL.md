# Nanopore Modkit DMR

## Scope

Use this skill only after `nanopore-modkit-pileup` has produced bedMethyl files. `modkit dmr` does not consume BAM directly.

Reference facts checked from upstream documentation:

- `modkit dmr` provides `pair` and `multi`.
- Inputs must be bedMethyl files created by `modkit pileup`, compressed with bgzip, and indexed with tabix.
- `dmr pair` can compare a pair of conditions at regions from a BED file or at single base positions when `--regions` is omitted.
- `dmr multi` requires an output directory and compares multiple named samples across regions.
- For 5mC, use `--base C`.

Source: https://nanoporetech.github.io/modkit/intro_dmr.html.

## Required Inputs

- `A_BEDMETHYL`: one or more bgzip bedMethyl files for condition A.
- `B_BEDMETHYL`: one or more bgzip bedMethyl files for condition B.
- `.tbi` index for every bedMethyl file.
- `REFERENCE_FASTA` and `.fai`.
- `OUTDIR` and comparison name.
- Optional `REGIONS_BED` for region-level DMRs.
- Optional `SEGMENT_BED` for single-site DMR segmentation.

## Mandatory Preflight

```bash
modkit --version
test -f "${REFERENCE_FASTA}.fai" || samtools faidx "${REFERENCE_FASTA}"
for bm in "${A_BEDMETHYL}" "${B_BEDMETHYL}"; do
  test -s "${bm}"
  test -s "${bm}.tbi"
  gzip -t "${bm}"
  tabix -p bed "${bm}" >/dev/null 2>&1 || true
done
```

If a bedMethyl file is plain `.bed`, compress and index it before DMR:

```bash
bgzip -k sample.5mC.bed
tabix -p bed sample.5mC.bed.gz
```

Do not run DMR on non-modkit methylation tables until they have been converted to modkit-compatible bedMethyl.

## Pairwise Region-Level DMR

Use this when the user provides regions such as genes, promoters, TE intervals, CG islands, candidate QTL intervals, or tiled windows:

```bash
mkdir -p "${OUTDIR}/dmr" "${OUTDIR}/logs"
modkit dmr pair \
  -a "${A_BEDMETHYL}" \
  -b "${B_BEDMETHYL}" \
  -o "${OUTDIR}/dmr/${COMPARE}.regions.dmr.bed" \
  -r "${REGIONS_BED}" \
  --ref "${REFERENCE_FASTA}" \
  --base C \
  --threads "${THREADS:-8}" \
  --header \
  --log-filepath "${OUTDIR}/logs/${COMPARE}.dmr_pair.log"
```

Clean BED region files to at least 3 columns and no header before running. Keep column 4 as the region name when available.

## Pairwise Single-Site DMR

Use this when the user asks for base-level differential 5mC positions:

```bash
modkit dmr pair \
  -a "${A_BEDMETHYL}" \
  -b "${B_BEDMETHYL}" \
  -o "${OUTDIR}/dmr/${COMPARE}.single_site.dmr.bed" \
  --ref "${REFERENCE_FASTA}" \
  --base C \
  --threads "${THREADS:-8}" \
  --header \
  --log-filepath "${OUTDIR}/logs/${COMPARE}.single_site.dmr.log"
```

Optional on-the-fly segmentation:

```bash
--segment "${OUTDIR}/dmr/${COMPARE}.single_site.segments.bed"
```

Add `--fine-grained` only when the user wants less aggressive segment merging.

## Replicates

For biological replicates, repeat `-a` and `-b`:

```bash
modkit dmr pair \
  -a condA_rep1.bedmethyl.gz \
  -a condA_rep2.bedmethyl.gz \
  -b condB_rep1.bedmethyl.gz \
  -b condB_rep2.bedmethyl.gz \
  -o "${OUTDIR}/dmr/${COMPARE}.replicate_aware.dmr.bed" \
  --ref "${REFERENCE_FASTA}" \
  --base C \
  --threads "${THREADS:-8}" \
  --header \
  --log-filepath "${OUTDIR}/logs/${COMPARE}.replicate_aware.dmr.log"
```

Preserve replicate order when the experiment has matched pairs.

## Multiple Samples

Use `dmr multi` when comparing more than two named samples over the same regions:

```bash
modkit dmr multi \
  -s sampleA1.bedmethyl.gz sampleA1 \
  -s sampleA2.bedmethyl.gz sampleA2 \
  -s sampleB1.bedmethyl.gz sampleB1 \
  -o "${OUTDIR}/dmr/${COMPARE}.multi" \
  -r "${REGIONS_BED}" \
  --ref "${REFERENCE_FASTA}" \
  --base C \
  --threads "${THREADS:-8}" \
  --header \
  --log-filepath "${OUTDIR}/logs/${COMPARE}.dmr_multi.log"
```

If many samples should be compared against one control, use `--ref-sample CONTROL_NAME`.

## Output Interpretation

For region-level output, important columns include score, sample A/B counts, sample A/B totals, sample A/B modified percentages, fraction modified, effect size, and optional Cohen's h confidence intervals.

For single-site output, MAP-based p-value and effect-size columns are added. Always keep the `--header` output and parse by column names because the schema changes between region and single-site analyses.

Report:

- input bedMethyl files and tabix index status.
- `--base C` and any custom `--assign-code` use.
- whether analysis was region-level, single-site, segmented, replicate-aware, or multi-sample.
- number of output rows and top regions/sites by absolute effect size.
- biological direction: positive or negative effect depends on A versus B ordering, so state the ordering explicitly.

## Common Failure Modes

| Symptom | Meaning | Fix |
|---|---|---|
| DMR refuses input | bedMethyl is not bgzip+tabix indexed | `bgzip` and `tabix -p bed` |
| No comparable sites | pileups used different scopes, references, or chromosome names | rerun pileup consistently |
| Confusing direction | condition order was not documented | report A and B paths in final answer |
| Custom mod code ignored | code is not recognized as cytosine | use `--assign-code <mod_code>:C` only when justified |

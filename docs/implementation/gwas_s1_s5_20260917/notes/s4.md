# S4：完整 Recovery 请求预算与正式外置读取

本切片在独立候选 `/tmp/biomind-gwas-s1-s5-20260917/s4` 实施。生产代码仅涉及 `bio_agents.py`、`agent_core/workflow/{recovery_agent,recovery_runtime,recovery_node,recovery_context,recovery_tools,inspection_evidence,phase_archive}.py`。根集成人负责与 S5 的 `recovery_node.fail()` 阶段标记串行合并；S5 前提清单、各源文件基线与候选 SHA256 见 `../evidence/s4_budget_receipts.json`。

## 实施

1. `project_recovery_seed_for_provider()` 保留既有字段、身份、规范序列化、字符遥测与对象保护，解除 32,000 字符值对模型准入的提前否决。完整请求仍经过既有 token 计量、维护触发、有限压缩、coverage 校验与硬容量准入。本轮没有全面去重 seed、改变 27 个引用身份或减少继承材料。
2. `resolve_recovery_budget_policy()` 从当前配置 reserve、已知业务/压缩客户端显式上限与已启用资源策略取共同有效输出上限。Node 和 Loop 使用相同策略；请求级 ContextVar 将该策略送到已有 BioAnalyst 最终适配器。最终边界重新计量实际 messages、绑定 tools，并显式 bind/传递 `max_tokens`，在 `ProviderAttemptEnvelope.output_policy` 留下回执。预算、实际 cap 与请求计量不一致时拒绝。仅影响 Recovery 业务与其 compactor，不降低其他节点上限。
3. 关闭前最后一次决定的提示原来在预算快照后追加，现先无副作用预览，完整计量后才提交原有单次决定状态；未准入的压缩边界不消耗该决定机会。
4. 裸 provider callable 若既不能 bind、又不接受 `max_tokens`/`**kwargs`，在真实调用前以 `RECOVERY_OUTPUT_CAP_UNSUPPORTED` 拒绝。兼容的测试 provider 叶子显式接受 cap，不能把仅生成回执当作真正约束输出。
5. 外置观察继续保存到现有 PhaseArchive，其不可变 invocation anchor 是发布记录。新增元数据冻结 task/plan/plan_version/step/attempt/episode、revision=1、内容摘要和 `evidence.read` 权限。正式 dispatcher 对当前持久作用域、引用、版本、内容与权限验证后，在既有临时 inspection registry 登记同一 handle，并复用正文分页组件读取；不建平行持久 registry。旧普通 phase archive 不因此获得读取授权，缺少该正式元数据的历史观察不会伪造升级为已授权正文。
6. `PhaseArchiveStore.read(..., max_object_bytes=...)` 只在新 observation 读取中指定现有 2 MiB 上限；对象和 invocation anchor 在解码前以有界读取检查，拒绝 symlink 路径。省略参数的一般 archive 行为保持原契约。上限包含 archive wrapper，超限返回 `INSPECTION_OBJECT_SIZE_LIMIT`。分页仍为最多 120 行、16,000 字符，长 JSON 行沿用既有 chunk envelope。
7. 已返回的正式 observation page 不再次外置，重复相同页仍由既有进展签名计算为无进展。最终适配器继续携带原 `receive_char_limit`，超量响应保持 ProviderAttempt 的 `PROVIDER_OUTPUT_LIMIT` 拒绝；没有因为新增预算分支解除响应保护。

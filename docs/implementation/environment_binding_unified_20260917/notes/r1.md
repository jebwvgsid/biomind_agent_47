# R1 — rollback、持久化及正式重跑

本子任务只修改 `agent_core/plan_tracker.py` 的 rollback/audit/migration 接线与 `agent_core/plan_bindings.py`。原有资源分配修改保持不动；未修改 bio_agents 或 Skill。

- `_apply_upstream_step_rollback` 复用实际 `{target,*affected}`，精确失效所有同 Plan id/version/revision 的 producer accepted 记录，保留值、历史、stale reason；`invalidate_descendants=False` 仍只失效原实现实际选择的 target+failed。
- 既有 Recovery `decision_audit` 补充 Plan revision、事件 generation 和实际失效 binding IDs。重复正式 decision 继续由原幂等入口保护，不会对重跑新值再次应用旧 rollback。
- `migrate_plan_state` 是唯一兼容修复入口。新事件按明确 IDs；旧事件按 affected、完整 Plan/producer scope、正式 Commit generation 或严格有时区时间先后修复残留。既有 Commit receipt 的 accepted refs 和 after_state_generation 作为顺序依据；保存/重载都使用同一实现。未向每个 reader 加状态 gate。
- 旧 audit 缺 Plan revision 或不可判定先后时，保留记录并产生 `task_state.plan_binding_reconciliation_diagnostics`，含 binding/producer/decision 与 `PLAN_BINDING_ROLLBACK_SCOPE_UNVERIFIABLE` 或 `PLAN_BINDING_ROLLBACK_ORDER_UNVERIFIABLE`。不猜时区，不凭现步骤状态撤销可能已经重跑正式提交的新值；诊断投影可由主任务 C2 消费。

新测试 5 项通过，使用真实临时磁盘 Plan store/CAS、原 Supervisor 确定性验证、CompletionGate、CommitStep 和精确 resolver；只有执行结果与可选模型 reviewer 是隔离夹具。覆盖：a→b→c rollback、无关 d 不变；reload 后 a/b 新值正式 Commit 为 revision 2；下游精确消费新 identity/value；旧事件 replay 不撤销新 Commit；有效值仍报 `PLAN_BINDING_IMMUTABLE`；加载旧残留后保存修复；有限回滚和同名异 Plan 历史保护；缺历史具体诊断。

# F3 — 拒收首因、实际纠正进展与同源预算

本次在现有 Generate 节点、candidate receipt/CAS ledger 和 RecoveryPolicy 中完成 IG-D4、IG-D5、G11 的窄修。没有新增全局 validator、Controller、语义 binder、进展状态机或预算体系。

当前验收指向候选 **08：F3 33 PASS**（原 28 项加 env 精确进展 5 项），独立 Recovery claim 重载 **1 PASS**；公共调用方 39 项为 **38 PASS / 1 原有断言 FAIL**。实际 source manifest、原始回执和历史失败分别见 [F3 总账本](f3_verification.json)、[env before/after](f3_env_progress.md)、[Recovery 独立 owner](f3_recovery_claim.md) 和 [公共调用方回归](regression/final08/README.md)。停止报告的来源补证单独见 [首因来源](f3_stop_origin.md)。这些组件通过不替代完整 F6 或真实模型/科学 E2E。

## 行为变化

- `env` 显式 list/null/string、子项非字符串都由实际 parser 给出精确 field/expected/actual；`code/body/command` 与 `operation` 非字符串也明确拒收。坏候选身份走完整候选的确定性指纹，不再进入合法执行动作的 `dict(env)` 归一化。原始公开业务回复完整 hash、选中容器/扫描来源及有界 parser excerpt hash 分别保留；CLI 不复制完整长正文。
- parser 仅在检查实际通过后记录目标。JSON 解码、action_type、argv/可执行正文、outputs、env 父对象与已验证子项逐层可比较；前置不满足时后段不被记为已通过。实际 script block 解析、两入口 helper 物化、真实语法检查成功还会分别传入节点自有 checkpoint；失败时没有该事实。格式阶段的 binding 轴为 `not_evaluated`，不会再用相同空 `binding_env` 覆盖真实格式修正。
- env 验证事实不依赖键顺序，首错误仍保持原 parser 反馈。逐字段续额仅对应上一精确未决字段；删除非必填坏键和真实键形状修正有直接验证，无关合法字段与 prose 不产生进展。重复上下文独立于诊断集合版本；旧行缺新检查点也不能借此续额，旧行不写回。
- 现有 ledger 作唯一纠正判断，记录 `progress_assessment`；generated-semantic 下层消费同一个可信决定，不再按脚本身份重新否决它。错误码变化和新旁白均不构成进展。不能证明新目标通过时使用 `GENERATE_REPAIR_NO_VALIDATED_PROGRESS`，不冒称已证明候选相同或科学失败。
- 完整候选先经过当前正式准入，再决定是否需要另一轮纠正。移除了准入前的旧 identical 快捷停止，因此最后一次合法回复与正式 blocked 保留各自合法分支。
- 比较视图只移除 action/candidate event ID 和 Recovery 临时 ID/route；正式候选及其完整 hash 不变。程序、资源/权限、效果义务、generation mode、Plan/schema/evidence 版本仍参与比较。A/B/A 与 UUID 换壳可识别为同一坏候选。
- 下一次实际 provider request 通过现有反馈装配收到准确错误、已通过/已解除/未满足目标、binding 评估状态；仅投影公开比较结论，不发内部比较指纹或权威 producer 对象。当前 mode 示例与停止出口由 F1 的同一 prompt 装配供应。

## 旧状态与预算

`candidate-corrections-v2`、默认 4 次额外 Generate 调用、作用域和 claim 单位均未修改。旧记录使用已冻结 cap；已停止行直接复用停止结果，不因新进程或新默认值复活。同 event 重投复用原 receipt，无 CAS generation 增量或重复扣额；未知调用保留已有 claim，完成后的精确重投与独立子进程重载复用同一内容和 claim。

旧 repairable 行若缺新增比较摘要，从其既有 `recovery_context.action_contract.structured_candidate` 核对完整原 hash 后，用当前实际 parser 重算比较视图。这是兼容读取，不重写旧事实、receipt、cap、status 或调用计数。没有可核对旧候选时不编造历史检查事实。

## 验证范围

可复核结果见 [f3_verification.json](f3_verification.json)。新测试以正式生产构造和 graph 完成 Consultant → Plan → 真实冻结审批 → TypedGenerate/parser/ledger。四组保持相同可执行 argv 的序列（env list/null/string 及 `{}` 外壳）验证 JSON 错误 → 缺 type → env 父类型 → env 子类型 → 第五次合法候选；只有四次额外授权，末次仍能成为 action_ready。另覆盖剩余额度的正式 blocked、真重复、UUID、A/B/A、错误码/旁白无新事实、旧诊断摘要兼容及原 rejection event 精确重投。两条新增真实 graph 序列分别把 helper 作用域错误或语法错误修正后，继续到另一项真实 operation 准入错误，再生成合法动作；已通过 checkpoint 不会因错误层级变化被丢弃。helper checkpoint 只表示当前物化调用成功，不声明运行、发射效果或科学成功。

取消测试在 provider await 时调用真实 `_commit_user_cancellation`。late-valid/invalid/blocked 三类均走 `stale_result`，由 approval applicability 失效收回结果，再进入 cancelled 终态；没有新 pending action、代码审批或执行。只增加非语义诊断 note 的 state_generation 变化仍接纳合法候选。

本组停止于 action_ready 或正式停止，**不冒充执行/Commit 全链通过**。新审批、真实小进程执行、证据、Commit 与执行后 Recovery 的组合验收由 F6 集成测试提供。模型是固定 provider；科学能力未提供；沿用既有 graph fixture 的 readiness/memory stub 均在证据中注明。原 session、原批准脚本、正式科学输入、provider/API、科学工具均未使用。子进程重载使用继承离线 guard 的 `fork`，没有 shell/profile 执行。

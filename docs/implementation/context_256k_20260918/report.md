## 配置口径与实际边界

新增明确的 `SCHEMA2_INPUT_SOFT_LIMIT_TOKENS`，环境变量 `BIOMIND_INPUT_SOFT_LIMIT_TOKENS`，默认 **256,000 tokens**。旧 `SCHEMA2_APPLICATION_CONTEXT_LIMIT_TOKENS` 仍表示输入与输出共用的总窗口上限，默认 **200,000**，没有改名换义或伪造更大的服务端能力。

有效输入维护边界取输入软目标与「已知有效总窗口 − 实际输出预留 − 估计余量 − 安全余量」的较小者；保留显式配置的提前触发策略。模型适配器 `context_window` / `max_context_tokens`、绑定客户端及 profile 能力共同收紧已有总窗口上限。`profile.max_input_tokens` 无总窗口说明时保守用作上界，不借此增大容量。

| 总窗口证据/测试条件 | 输入软目标 | 输出预留 | 现有余量 | 实际维护边界 |
| --- | ---: | ---: | ---: | ---: |
| 当前 legacy 总窗口上限；远端能力未知 | 256,000 | 50,000 | 4,096 + 2,048 | 143,856 |
| 模拟明确 256,000 窗口的适配器 | 256,000 | 50,000 | 4,096 + 2,048 | 199,856 |
| 模拟明确 400,000 窗口且应用上限足够 | 256,000 | 50,000 | 4,096 + 2,048 | 256,000 |

不能将第一行宣传为服务端支持 256k 输入。各普通节点沿用最终绑定客户端的输出设置；Recovery 不因输入压力静默降低 50k。没有重新向用户询问倍性，压缩回归固定保留 `PLOIDY=2`、批准路径及节点协议。

计量沿用 `ReferenceTokenEstimator`：可用时为 cl100k 参考 tokenizer，否则使用已有混合文字估计；两者都标记 `estimated` 并记录名称、版本、不确定量。它不是当前远端模型的精确计费 token。边界测试使用明确标注的可控估计器，另外测试生产配置真实解析。服务端窗口包含输入及生成预留的口径参考 [OpenAI 上下文说明](https://developers.openai.com/api/docs/guides/conversation-state#managing-the-context-window)；原生工具交互与签名保真参考 [Claude 上下文说明](https://platform.claude.com/docs/en/build-with-claude/context-windows)。本轮不迁移 provider。

## 处理顺序、恢复与原因归属

1. 当前响应及合法工具组完整闭合，每个结果先保存；下一次普通模型请求才判断是否压缩。最新工具组标记为必须原样保留，不能在尚未进入下一请求时被选择器丢掉。乱序结果按 tool_call_id 对应，原生参数字符串、附加 thinking/signature 不被重新规范化。
2. 完整合法最终 directive 直接接纳；没有下一轮就不额外压缩。残缺/截断响应仍走原有限重提协议。
3. 活动阶段复用原压缩状态和历史偏移，验证源前缀与节点身份后仅拼接新增消息，避免每个工具续轮重新压缩同一旧历史。
4. Recovery 复用原事件日志和 CAS 历史切换。工具落盘至消息入队之间、摘要完成至切换之间、切换提交之后的中断均有回归。已落盘工具不重复执行；业务累计字符数、轮数和工具次数不因压缩归零。原 12 轮 / 24 工具限制不增加。
5. 发现并修复维护计数持久化缺口：压缩调用预留及结算写入原 boundary journal。历史尚未切换时中断，下一次进程入口也不会获得新的维护次数/token 额度。
6. 压缩失败时保留旧历史和证据。硬窗口内按原机制提供一次安全回退；不安全请求停止于准确的维护/容量错误。真实重复调查仍可触发 NO_PROGRESS，变化的 timing 不构成科学新证据。

单条未达到字符分页阈值、但同组总量过大的结果，也会按当前请求的 token 容量份额使用已有外置归档机制。16 条同组结果全部完整落盘、各带身份与引用进入下一请求；这个规则只改变单次显示方式，不使用历史累计字符，不拒收工具结果。外置后的无进展判定依据原始结果的科学证据投影，不依据归档地址、遥测长度或分页维护字段；大、小重复结果均有回归。

## 证据和遥测

# B2 — 父证据引用与可应用、有成本上限的压缩

沿用现有 InspectionObjectReader、RecoveryAgentLoop、context_compaction、PhaseArchiveStore 和 PlanState CAS。

- causal_history 只保存父 packet/decision、原始证据的 ref/digest/scope/revision 和工具读取回执索引。历史正文仍在原对象中；`evidence.read` 的可选 `causal_path` 逐个验证显式授权的父引用，最多 8 层，每页最多 120 行/16,000 字符。跨任务、未授权引用、哈希变化和取消后的读取拒绝。
- inherited 材料仅按同源、同 hash、同 scope/revision/coverage 等完整身份去重；同文不同来源保留。
- compactor 的完整响应 schema 与严格解析器共用 dataclass 字段。保护材料的精确保留策略在 map 前确定；必要时才允许 capacity_pressure。全部材料受保护且输入安全时不浪费模型调用。
- map 缓存只接收完整校验通过的结果。新 request/epoch 和工具尾部不使未变源失效；来源、hash、scope、revision、范围或 prompt 变化则不误复用。复用已有容量分段前重新检查完整 wire。
- 一个维护账本跨 map、merge、final-plan、局部格式重试和安全回退累计：最多 64 次调用、累计收费/预留最多 2 × 有效 context limit、300 秒累计维护时间。UNKNOWN 使用输入估计加输出预留，绝不按零。现有单次格式重试上限仍为 2。
- 失败最多提供两次经硬上限检查的安全业务请求机会；不安全则明确停止。合法 epoch 先归档、再 CAS、再交给下一请求；应用后只给一次仍需硬上限校验的业务机会，避免受保护材料高于软目标时立即重复压缩。
- coarse 活动事件区分模型返回、拒绝、已应用和取消。显示观察失败不替代存储/核验权威。

定点定位：0044/0058/0076 各含同一个 299,348 字符的完整源正文（不是三个不同范围）。阶段 A 的 108906/108897/108900 prompt usage 保持为历史值。父正文引用化与通过身份校验的 map 复用分别处理内容膨胀和重复维护成本；本轮不产生新的真实 usage。

验证：`test_compaction.py` 与 `test_causal_history.py` 共 10 项通过。实际 archive/CAS/下一请求、失败后修正、取消与预算触边接线结果在 B3 总交付中汇总。

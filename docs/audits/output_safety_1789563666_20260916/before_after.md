# 用户可见行为与边界

| 情形 | 修改前的缺口 | 当前行为 |
| --- | --- | --- |
| 指定 ann.vcf，文件已存在 | 普通代码批准没有单独列出旧文件保留动作 | Consult 先有限查看并交接冲突；Plan 保留所需名称；代码审批列出实际旧文件与备份位置，输入 `backup` 才允许先备份后替换 |
| 误按 Enter / y | 普通批准可能被当成替换许可 | 同一审批继续等待，不调用 Generate、不启动命令 |
| 审批后文件或父目录变化 | 缺少绑定于审批的旧文件状态 | 本次命令不启动；重新检查目标并取得当前版本的审批 |
| 可选产物路径已物化且旧文件存在 | 正式必需输出集合遗漏 optional 保护 | 独立保护集合包含 optional，正式必需性不变 |
| helper 同时报 ann_summary 与 output.ann_summary | 原始候选到执行时才报身份不符 | 能静态确定时在 Generate 准入反馈代码位置；原局部纠正下一请求可见；修正后一次审批、一次执行到 Commit |
| 失败 attempt 的未登记文件可能已经存在 | Recovery 缺 locator | 仅在当前 attempt 执行/路径/权限证据吻合时诊断读取；明确来源尚未确认，不升级 valid head |
| 反复无进展 | 停止后还请求模型总结且说明混乱 | 原预算停止；零额外总结模型，按持久事实给出简短解释 |
| 分析中缺必需文件 | 容易混淆找不到、未登记、未生成 | 提示先证据定位再用原 Recovery 决定；需要删减必需目标时走用户决定和 TaskSpec/Plan 修订，不静默跳过 |

原始问题：证据登记含未声明的标识 output.ann_summary（声明标识：ann_summary；EFFECT_FACT_IDENTITIES_MISMATCH）。

本次调查：2 次模型请求，3 次工具调用；不是全会话累计。

这是一份离线注入事实的显示见证，不代表历史任务已修复。完整细节继续通过既有入口查看。启动前文件保护不等于任意代码的操作系统隔离；未声明写入与外部并发竞争仍是明确边界。
